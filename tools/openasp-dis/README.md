# openasp-dis

`openasp-dis` is used to verify and disassemble the `.oac`
bytecode image generated by `openasp` or OpenASP FPM.
It reuses the runtime image decoding and bytecode verification logic. Files that are damaged, truncated, ABI mismatched, checksum errors
or have illegal instructions will be rejected.

## Build

```sh
make build/bin/openasp-dis
```

The full build and minimal profile will also be generated separately:

```text
build/bin/openasp-dis
build/minimal/bin/openasp-dis
```

## Use

to directly compile and execute a page and save the same bytecode that the VM actually executes:

```sh
build/bin/openasp /srv/www/page.asp --root /srv/www \
    --emit-oac /tmp/page.oac --gen-dbg-info=on
build/bin/openasp-dis /tmp/page.oac
```

`--emit-oac FILE` is equivalent to `--emit-oac=FILE`, the target file must end with `.oac`.
writes using temporary files in the same directory and atomic replacement, leaving no half-image that can be misread.
`--gen-dbg-info` defaults to `off`; when set to `on` OAC only includes normalized source code.

FPM's disk L2 cache also generates OAC. First enable the source code
debugging information in the `openasp-fpm` configuration file:

```yaml
gen-dbg-info: on
opcache-dir: /tmp/openasp-opcache
```

can also be enabled via the command line:

```sh
build/bin/openasp-fpm --gen-dbg-info=on --opcache-dir /tmp/openasp-opcache
```

After the page is requested at least once, FPM generates an
`.oac` file named with the 16-bit cache key hash in `opcache-dir`. Disassemble using the following command:

```sh
build/bin/openasp-dis /path/to/cache/0123456789abcdef.oac
```

Without parameters or using `--help` you can view the command format:

```text
Usage: openasp-dis <file.oac>
```

## Output format

The file header provides overall information about OAC:

- `File`: The OAC file being read.
- `Size`: The total number of bytes of the OAC file.
- `Source`: cache type, debug mode and raw ASP path. `P:D:` indicates the page cache and contains debugging information.
- `Instructions`: Total number of instructions.
- `Max stack`: Verified VM maximum operand stack depth.
- `Loops`: Number of loops recognized by the compiler.
- `Debug info`: Whether to save the normalized ASP source code.

After the file header, dependencies, modules, names, constants, global slots, routines and class metadata are displayed in order, and finally the
`.oasp_bytecode` command area.

Each instruction uses GDB `disassemble /m` and `disassemble /r` style:

```text
0x00000000000006f8 <Classify+96>:  37 ... 00  jump_if_true  0x00000000000007e8 <Classify+336>
```

- `0x00000000000006f8`: The actual byte offset of the instruction in the OAC file, not the process address affected by ASLR.
- `<Classify+96>`: Current symbol and byte offset relative to routine entry.
- `37 ... 00`: The complete 24-byte instruction encoding saved unchanged in OAC, displayed in hexadecimal.
- `jump_if_true`: OpenASP VM opcode mnemonic.
- `0x... <Classify+336>`: OAC offset and symbolic position of the jump target.
- `# String("alpha")`: The result of parsing the constant, name, or global slot operand.

When debugging information is enabled, the source code line number and normalized ASP source code are displayed before the corresponding command group:

```text
    4        Case "alpha", "beta", "gamma"
```

`__asp_page` represents the top-level code of the page. Function, Sub, Property and class code are chunked using their own symbolic name
, with boundaries marked with `Dump of assembler code` and `End of assembler dump.`.

## Instruction encoding

The "machine code" here is the fixed 24-byte opcode encoding actually executed by the OpenASP VM, not the
ARM64 or x86-64 CPU native instruction. The byte layout is:

| byte offset | width | field |
| --- | ---: | --- |
| `0x00` | 1 | `opcode` |
| `0x01` | 1 | `flags` |
| `0x02` | 2 | `reserved` |
| `0x04` | 4 | `line` |
| `0x08` | 4 | `target` |
| `0x0c` | 4 | `error_target` |
| `0x10` | 4 | `operand` |
| `0x14` | 4 | `slot` |

The hexadecimal bytes match the OAC file contents byte-for-byte. The address column can be directly used as a file offset and checked with tools such as
`xxd`:

```sh
xxd -g 1 -s 0x6f8 -l 24 /tmp/openasp-opcache/6d30fb6d901ff936.oac
```

## No debug information

`gen-dbg-info` defaults to `off`. At this time, OAC does not contain the source code segment. The disassembler still displays the complete
symbol, hexadecimal encoding, opcode and operand, but the file header displays:

```text
Debug info: unavailable
```

The command area does not display ASP source lines.

## Checksum errors

The disassembler reuses the runtime decoder to check magic, ABI, range, alignment, checksum and
bytecode validity before output. Corrupted, truncated, or version-mismatched files return a non-zero status; the current error lists
as a possible validation class failure, but the decoder does not yet distinguish the specific failure stage.

The `.oac` file name in the FPM secondary opcode cache is the hash value of the cache key;
`openasp --emit-oac` uses the file name explicitly specified by the user.
The cache directory is configured by `opcache-dir` and is located in the system temporary directory by default.
